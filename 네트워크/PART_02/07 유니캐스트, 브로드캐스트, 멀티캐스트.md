# 07. 유니캐스트, 브로드캐스트, 멀티캐스트

# 유니캐스트 Unicast

![image.png](image.png)

- 특정 PC 1개에게 데이터를 보내는 1:1 통신 방식
- 프레임 = 출발지 MAC 주소, 목적지 MAC 주소
- 랜카드가 목적지 MAC주소 확인
    - 자신의 MAC 주소와 다르면 프레임 버림
    - 자신의 MAC 주소와 같으면 CPU 전달
- 수신 대상이 아닌 PC의 CPU는 부담이 없음
- 가장 많이 사용되는 일반적인 네트워크 통신 방식

# 브로드캐스트 Broadcast

![image.png](image%201.png)

- 같은 로컬 네트워크(같은 브로드캐스트 도메인)에 연결된 모든 장비에게 데이터를 보내는 방식
- 목적지 MAC 주소 = `FF:FF:FF:FF:FF:FF`
- 모든 랜카드는 이 주소의 프레임을 받으면 CPU에 전달
    
    → 모든 PC의 CPU인터럽트와 처리 부담 多 → PC 성능 저하
    
- 대표적인 사용 사례 = ARP
    
    ![image.png](image%202.png)
    
    ```jsx
    1. 상대의 IP주소만 알 때
    2. 이 IP 주소는 누군인가, 라는 요청을 전체에 브로드캐스트
    3. 해당 장비가 MAC 주소로 응답
    ```
    

# 멀티캐스트 Multicast

![image.png](image%203.png)

- 특정 그룹에 가입한 네트워크에게만 데이터 한 번에 보내는 방식
- 유니캐스트의 정확성 + 브로드캐스트 효율
- 스위치, 라우터가 멀티캐스트 지원해야함
    
    → 지원 안하면 브로드캐스트 혹은 라우터에서 차단
    

# 요약

| 방식 | 전송 대상 | 특징 |
| --- | --- | --- |
| 유니캐스트 | 특정 1대 |   • 가장 일반적인 1:1 통신
  • 다른 PC 부담 少 |
| 브로드캐스트 | 같은 네트워크 영역의 모든 장비 |   • ARP에 사용
  • 모두가 받아 처리하므로 성능 저하 가능 |
| 멀티캐스트 | 특정 그룹 구성원들 |   • 불필요한 트래픽과 CPU 부담 줄
  • 필요한 그룹에만 한 번에 전달 |

## 부록. 애니캐스트 Anycast

![image.png](image%204.png)

- 같은 주소를 여러 서버가 공유, 네트워크 상 가장 가깝거나 경로가 좋은 한 곳으로 데이터 전달
- DNS, CDN, DDoS 방어, 대규모 서비스 접속 분산
- 실제 물리적 거리보다 라우팅 경로(BGP)가 가장 좋다고 판단한 서버
- 여러 요청이 항상 동일한 서버에 도착한다는 보장 X
    
    → 연결 상태 유지해야하는 별도 설계 필요
    
- 용어 설명
    - DNS (Domain Name System)
        
        사람이 읽는 도메인을 IP주소로 바꿔주는 시스템
        
    - CDN (Content Delivery Network)
        
        이미지, 영상, 웹 파일 등 여러 지역의 서버에 복제 → 사용자에게 가까운 서버가 전달되도록 하는 서비스
        
    - BGP (Border Gateway Protocol)
        
        서로 다른 인터넷이나 대형 네트워크 사이에서 IP 주소 대역으로 가기 위한 경로를 알려주는 라우팅 프로토콜
