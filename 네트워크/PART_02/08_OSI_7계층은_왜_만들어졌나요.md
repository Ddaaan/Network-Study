# OSI 7계층

## OSI 7계층이란?

- OSI(Open Systems Interconnection) 7계층은 ISO(국제표준화기구)가 만든 모델
- 통신이 일어나는 과정을 7개의 단계로 나누어 표준화
- 통신의 효율성을 높이기 위해 사용함
<br>

**OSI 7계층의 순서**

1. Application Layer (애플리케이션 계층)
2. Presentation Layer (프레젠테이션 계층)
3. Session Layer (세션 계층)
4. Transport Layer (트랜스포트 계층)
5. Network Layer (네트워크 계층)
6. Data Link Layer (데이터 링크 계층)
7. Physical Layer (피지컬 계층)

## 7계층으로 굳이 왜 나누는데??

### 1. 데이터 흐름을 한눈에 볼 수 있다

애플리케이션 계층부터 마지막 피지컬 계층까지 나누어 두었기 때문에, 데이터가 어떤 과정을 거쳐 전달되는지 보기 쉽다.

### 2. 문제 해결이 편리하다

네트워크 문제가 발생했을 때 문제를 7개의 작은 영역으로 나누어 확인하면 훨씬 쉽다.

- 이메일이 되지 않을 때 `ping`으로 인터넷 연결을 확인할 수 있다.
- ping은 네트워크 계층에 속하는 프로그램이다.
- ping이 정상이라면 네트워크 계층까지는 이상이 없다고 보고, 그 위 계층부터 문제를 확인할 수 있다.
- 특정 계층까지 통신에 이상이 없다면 그 아래 계층에는 문제가 없다고 판단할 수 있다.
- 게임방의 모든 PC에서 인터넷이나 배틀넷 연결이 끊긴다면, 게임방 인터넷 접속이나 피지컬 계층 쪽 문제를 의심할 수 있다.

### 3. 장비와 기술을 함께 사용할 수 있다

계층을 7개로 나누고 층별로 표준화했기 때문에 여러 회사의 장비를 사용해도 네트워크가 동작한다. 케이블은 국산, 랜카드는 인텔, 스위치나 라우터는 시스코 제품처럼 서로 다른 장비를 함께 쓸 수 있다.


## 계층별 설명

### 1계층: Physical Layer (피지컬 계층)

- 통신의 가장 아래 단계
- 전기적, 기계적, 기능적 특성을 이용해 통신 케이블로 데이터를 전송한다.
- 이 계층의 통신 단위는 비트(Bit)이며, `1`과 `0`로 통신한다.
- 데이터가 무엇인지, 오류가 있는지, 어떻게 보내는 것이 효율적인지는 관여하지 않고 데이터를 전달한다.
- 대표 장비: 통신 케이블, 리피터, 허브

### 2계층: Data Link Layer (데이터 링크 계층)

- 피지컬 계층을 통해 송수신되는 정보의 오류와 흐름을 관리한다.
- 안전한 정보 전달을 돕고, 통신 오류를 찾아 재전송하는 기능도 가진다.
- MAC 주소를 사용해 통신할 수 있게 한다.
- 전송 단위는 프레임(Frame)!
- 대표 장비: 브리지, 스위치

### 3계층: Network Layer (네트워크 계층)

- 데이터를 목적지까지 가장 안전하고 빠르게 전달하는 것이 중요한 기능이다.
- 경로를 선택하고 주소를 정하며, 경로에 따라 패킷을 전달한다. 이를 라우팅이라고 한다.
- 라우터가 속함
- 라우팅 기능을 수행하는 스위치는 보통 L3 스위치라고 한다.

### 4계층: Transport Layer (트랜스포트 계층)

- 주된 역할은 흐름 제어와 오류 복구
- 오류 복구를 위해 패킷을 재전송하거나, 흐름을 조절해 데이터가 정상적으로 전송되도록 한다.
- 트랜스포트 계층에 TCP와 UDP가 해당됨

## 이메일 전송 과정: 헤더와 포장

내 PC와 친구 PC 사이에서 이메일을 주고받는 상황을 생각할 수 있다.

### 송신 측

이메일은 7계층을 따라 아래로 내려가면서 계층마다 포장된다. 이 포장 앞에는 **헤더(Header)** 정보가 붙으며, 헤더에는 각 계층에서 관리하는 여러 정보가 들어간다.

- 예를 들어 네트워크 계층의 헤더에는 IP 주소가 붙는다.
- 가장 아래 피지컬 계층에서는 데이터가 컴퓨터가 이해하는 이진수, 즉 `1`과 `0`의 전기 신호로 바뀐다.
- 전기 신호는 네트워크 케이블을 통해 친구 PC로 전달된다.

### 수신 측

친구 PC에 도착한 데이터는 포장을 하나씩 벗기며 위 계층으로 올라간다. 각 계층은 내용에 이상이 없는지 확인한다.

- 레이어 4에서 포장을 열어 문제가 있으면 재전송을 요구하거나 오류 복구를 시도한다.
- 이상이 없을 때만 맨 위 계층까지 올라가며, 그때 친구는 보낸 이메일을 읽을 수 있다.

## 알아둘 점

데이터는 아래 계층으로 내려갈수록 헤더 같은 정보가 붙어 더 커진다. 따라서 실제 전송되는 데이터의 크기는 처음 만든 데이터보다 커지며, 전송 속도가 생각만큼 나오지 않는 한 가지 이유가 될 수 있다.
