## 도메인 네임과 네임서버

- **도메인 네임 : 호스트 IP주소와 대응되는 문자열 형태의 호스트 특정 정보**
    - ex) www.example.com, developer.naver.com와 같은 문자열이 도메인 네임
    - IP주소를 전화번호에 비유하면 도메인 네임은 전화번호에 대응하는 사용자 이름
    - ‘사용자 이름 : 전화번호’ 쌍의 목록을 전화번호부에 모아서 관리하는 것과 같이, **도메인 네임과 IP 주소를 네임 서버에서 관리**
    - 도메인 네임을 관리하는 네임 서버는 DNS 서버라고 부름

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/1.png)

위의 그림과 같이 도메임 네임을 네임 서버에 질의하면 해당 도메인 네임에 대한 IP 주소를 알려주는 방식으로 도메인 네임을 통해 IP주소를 알아낼 수 있음(반대로도 가능)

- **도메인 네임은 IP 주소에 비해 기억하기 쉽고, IP 주소가 바뀌더라도 바뀐 IP주소에 도메인 네임을 다시 대응**하면 되므로 IP주소만 호스트를 특정하는 것보다 간편

```jsx
www.example.com
```

- **도메인 네임은 점(.)을 기준으로 계층적 분류**
- **최상단에 루트 도메인(root domain)**
- **그 다음 단계인 최상위 도메인(TLD : Top-level Domain)이 있음**
- 그 다음 단계의 도메인이 있는 관계

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/2.png)

- www.example.com에서 **최상위 도메인**은 ‘com’
    - ex) com, net, org, kr(대한민국), jp(일본)
    - 일반적으로 최상위 도메인을 ‘도메인 네임의 마지막 부분’으로 간주
- 최상위 도메인의 하부 도메인은 **2단계 도메인**
    - ‘example’이 2단계 도메인
- ‘www’는 **3단계 도메인**
    - 일반적으로 3~5단계 정도
- **도메인 네임을 모두 포함하는 도메인 네임을 전체 주소 도메인 네임(FQDN : Fully-Qualified Domain Name)**이라고 함

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/3.png)

- FQDN의 첫번째 부분(www)을 호스트 네임이라고 부르기도 함
    - ‘호스트 네임’이라는 용어는 때로는 FQDN 자체를 가르키기도 하며, 때로는 네트워크상의 장치 자체 이름

</br></br>

## 계층적 네임 서버(DNS : Domain Name System)

- **계층적이고, 분산된 도메인 네임에 대한 관리 체계**
    - ‘IP주소를 모르는 상태에서 도메인 네임에 대응하는 IP주소를 알아내는 과정’을 흔히 ‘도메인 네임을 풀이(resolve)’한다고 표현하며, 영어로 ‘리졸빙(resolve+ing)한다’라고 표현

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/4.png)

- **로컬 네임 서버(local name server)**
    - **클라이언트와 맞닿아 있는 네임 서버**로, 클라이언트가 도메인 네임을 통해 IP 주소를 알아내고자 할 때 가장 먼저 찾게 되는 네임 서버
    - 로컬 네임 서버를 찾기 위해선, 로컬 네임 서버의 주소를 알아야 하는데 대부분 ISP에서 할당
        - ISP(인터넷 서비스 제공자, Internet Service Provider) : 개인이나 기업에 인터넷 접속을 제공하는 회사
            - ex) KT, SKT, LGU+ ..
    - 다만 ISP에서 할당해주는 로컬 네임주소가 아닌 공개 DNS 서버를 이용할 수도 있음
        - ex) 구글 : 8.8.8.8, 클라우드 플레어 : 1.1.1.1
- 로컬 네임 서버가 대응하는 IP 주소를 모른다면, 루트 네임 서버에게 해당 도메인 네임 질의, 루트네임서버는 질의에 대해 TLD 네임 서버의 IP주소 반환

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/5.png)

- **TLD 네임 서버:**  TLD를 관리하며, TLD에 대한 하위 도메인 네임을 관리하는 네임 서버 주소 반환 가능

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/6.png)

- **책임 네임 서버** : 특정 도메인 영역을 관리하는 네임 서버로, 자신이 관리하는 도메인 영역의 질의에 대해서는 다른 네임 서버로 넘기지 않고 곧바로 답할 수 있는 네임 서버
    - **로컬 네임 서버가 마지막으로 질의하는 네임 서버**
    - 계층적 구조를 띄고 있음


![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/7.png)

### 리졸빙하는 과정

- **IP 주소를 알아내는 과정**
- 로컬 네임 서버가 네임 서버들에게 질의하는 방법은 크게 ‘**재귀적 질의**’와 ‘**반복적 질의**’라는 두 가지 방법

#### 재귀적 질의

- 클라이언트가 로컬 네임 서버에게 도메인 네임을 질의하면, 로컬 네임 서버가 루트 네임 서버에게 질의하고, 루트 네임 서버가 TLD 네임 서버에게 질의하고, TLD 네임 서버가 다음 간계에 질의하는 과정을 반복하며 최종 응답 결과를 역순으로 전달받는 방식

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/8.png)

#### 반복적 질의

- 클라이언트가 로컬 네임 서버에게 IP 주소를 알고 싶은 도메인 네임을 질의하면, 로컬 네임 서버는 루트 도메인 서버에게 질의해서 다음으로 질의할 네임 서버의 주소를 응답받고, 다음으로 TLD 네임 서버에게 질의해서 다음으로 질의할 네임 서버의 주소를 응답받는 과정을 반복하다가 최종 응답 결과를 클라이언트에게 알려주는 방식

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/9.png)

- 도메인 네임을 리졸빙하는 과정이 복잡하고, 메세지 수가 많아짐
    
    → **네임 서버들이 기존에 응답받은 결과를 임시로 저장했다가 추후 같은 질의에 활용하는 DNS 캐시** 이용
    
- **DNS 캐시**
    - 짧은 시간 안에 원하는 IP 주소를 얻어낼 수 있음
    - 임시 저장된 값은 TTL(Time To Live)와 저장되어, 캐시될 수 있는 시간을 저장

## 자원을 식별하는 URI

- 자원(resource) : 네트워크상의 메세지를 통해 주고받는 대상
    - 오늘날 인터넷 환경은 대부분 HTTP 기반으로 이루어지므로, 자원이라는 용어는 ‘HTTP 요청 메세지의 대상’이라고 하기도 함

    ![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/10.png)
    

### URL(Uniform Resource Locator)

- 위치를 이용해 자원을 식별
- 아래는 인터넷 표준 문서(RFC 3986)에서 소개하는 일반적 URL 표기

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/11.png)

1. **scheme**
    - ‘자원을 접근하는 방법’ 의미
    - 일반적으로 사용할 프로토콜 명시
        - ex) HTTP를 사용하여 자원 접근 시, http:// 사용, HTTPS시, https:// 사용
2. **authority**
    - ‘호스트를 특정할 수 있는 정보’
    - IP 주소 혹은 도메인 네임 명시
    - 콜론(:) 뒤에 포트 번호를 덧붙일 수 있음
3. **path** 
    - ‘자원이 위치한 경로’
    - 자원으 위치는 슬래시(/)를 기준으로 계층적으로 표현되고, 최상위 경로 또한 슬래시
4. **query**
    - 쿼리 문자열, 쿼리 파라미터로 부름
    - 쿼리 문자열은 물음표(?)로 시작되는 <키=값> 형태의 데이터로, 엠퍼샌드(&)를 사용하여 여러 쿼리 문자열 연결

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_05/01/12.png)

5. **fragment**
    - ‘자원의 한 조각을 가리키기 위한 정보’
    - ex) URL중 HTML 자원의 특정 부분을 가르키는 경우
    
    ```jsx
    // 기본 URL
    https://datatracker.ietf.org/doc/html/rfc3986
    // 특정 부분을 가르키는 URL
    https://datatracker.ietf.org/doc/html/rfc3986#section-1.1.2
    ```
    

### URN(Uniform Resource Name)

- **이름을 이용해 자원을 식별**
    - URL은 위치 기반으로 자원을 식별하는데, 위치는 언제나 변할 수 있으며, 변경 시, URL로 자원을 식별할 수 없음
- 고유한 이름 기반 식별자이기에 **자원의 위치와 무관하게 자원을 식별할 수 있는 장점**이 있음

```jsx
//예시) ISBN이 0451450523인 도시를 나타내는 URN
urn:isbn:0451450523
```
