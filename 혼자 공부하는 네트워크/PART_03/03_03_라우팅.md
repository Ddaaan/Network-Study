## 라우터

- 멀리 떨어져 있는 호스트 간의 통신 과정에서 패킷은 서로에게 도달하기까지 여러 라우터를 거쳐서 다양한 경로로 이동
    
    ex) 집에서 지구 반대편의 친구에게 이메일을 보낸다면, 그 이메일은 여러 대의 라우터를 거쳐 마침내 친구에게 다다름
    
    → 패킷은 여러 대의 라우터를 깡충깡충 거치듯이 수신지까지 이동
    
- **홉 :** 라우팅 도중 패킷이 호스트와 라우터 간 or 라우터와 라우터간에 이동하는 하나의 과정

→ **패킷은 “여러 홉을 거쳐” 라우팅될 수 있는 것**

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/2.png)

ex) 웹 브라우저에 www.google.com을 입력해 구글 웹 페이지 확인하는 과정도, 웹브라우저가 구글의 컴퓨터와 패킷을 주고받는 과

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/3.png)

## 라우팅 테이블

- **특정 수신지까지 도달하기 위한 정보를 명시한 표와 같은 정보**
- 라우터는 라우팅 테이블을 참고해 수신지까지 도달 경로 판단
- 라우팅 테이블에 포함된 정보
    - **수신지 IP 주소와 서브넷 마스트** : 최종적으로 패킷을 전달할 대상을 의미
    - **다음 홉** : 최종 수신지까지 가기 위해 거쳐야할 호스트의 IP주소나 인터페이스를 의미, 게이트웨이라고도 함
    - **네트워크 인터페이스** : 패킷을 내보낼 통로, 인터페이스(NIC) 이름이 직접적으로 명시되거나 인터페이스에 대응하는 IP주고 명시
    - **메트릭** : 해당 경로로 이동하는 데에 드는 비용, 라우터가 라우팅 테이블에 있는 경로 중 패킷을 내보낼 경로를 선택할 때 메트릭 낮은 경로 선택
        - 네트워크 상에서 **비용**이란..?
            
            **목적지까지 가는 데 얼마나 불리한 경로인지 수치화한 값**
            
            - RIP → 지나가는 라우터의 개수, Hop Count
            - OSPF → 주로 링크의 대역폭을 기준으로 cost 계산
            - EIFRP → 대역폭, 지연시간 조합
            
            → **“비용을 무엇을 계산하느냐”는 라우팅 프로토콜마다 다름**
            

#### For example)

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/4.png)

- 수신지가 192.168.2.0/24(호스트 IP 주소 범위 192.168.2.1 ~ 192.168.2.254)인 패킷은 eth0(인터페이스)를 통해 192.168.2.1(게이트웨이)로 전송하라는 것을 의미
- 라우팅 테이블에 있는 수신지 IP주소, 서브넷 마스크 등 일치하지 않는 경우도 존재한는데(리우팅 테이블에 없는 경로로 전송 경우), 이러한 경우 **기본적으로 패킷을 내보낼 경로를 설정하고 해당 경로로 내보내는 것**을 **디폴트 리우트**라고 함

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/5.png)

- 윈도우의 경우 `route print` 로, 맥 OS나 리눅스 운영체제는 `netstat -rn` 의 명령어로 라우팅 테이블 확인 가능

#### 라우팅을 해주는 네트워크 장비인 라우터는 라우팅 테이블을 통해 패킷을 수신지까지 전달할 수 있고, 라우팅 테이블 안에는 네트워크상의 특정 수신지까지 도달하기 위한 정보들이 담겨져 있다.

## 정적 라우팅과 동적 라우팅

- 라우팅 테이블은 크게 정적 라우팅, 동적 라우팅으로 만들어짐

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/6.png)

### 정적 라우팅

- **사용자가 수동으로 직접 채워 넣은 라우팅 테이블의 항목을 토대로 라우팅 됨**
    
    ex) 10.0.0.0/24로 향하는 패킷을 192.168.1.1 게이트워이로 라우팅하는 명령어
    
    ![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/7.png)
    

### 동적 라우팅

- **자동으로 라우팅 테이블 항목을 만들고, 이를 이용해 라우팅하는 방식**
- 동적 라우팅의 경우 라우팅 테이블을 수시로 변경할 수 있음
    - 수동으로 입력하지 않아, 대규모 네트워크를 관리하는 데 있어서 편리
    - 네트워크 경로상에 문제가 발생했을 때 우회할 수 잇는 경로 자동 갱신

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/8.png)

- 어떻게 자동을 라우팅 테이블 항목을 만들지?
    - **모든 라우터는 특정 수신지에 도달하기 위한 최적의 경로를 찾아 라우팅 테이블에 추가하려고 노력**하는데, 이를 위해 라우터끼리 **서로 자신의 정보를 교환**
        
        → 이 과정에서 사용되는 프로토콜이 **라우팅 프로토콜**
        

#### AS

- Autonomous System의 약자로, **라우팅 정책으로 운용되는 라우터들의 집단 네트워크를 의미**
- **한 회사나 단체에서 관리하는 라우터 집단**
- AS마다 인터넷상에서 고유한 AS번호가 할당되고, 사설 IP처럼 사설 AS도 있지만, 일반적으로 AS 번호를 칭할 때 고유한 번호로 구분하기 위해 사용

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/9.png)

- 한 AS내에 다수의 라우터가 있으며, 라우터들은 AS 내부에서만 통신할 수 있고, AS 외부와 통신할 수도 있음
- AS 외부 통신할 경우 AS 내외로 통신을 주고받을 수 있는 **AS 경계 라우터** 라는 특별한 라우터 이용

## 라우팅 프로토콜

- **라우터끼리 자신들의 정보를 교환하며 패킷이 이동할 최적의 경로 찾기 위한 프로토콜**
- 라우팅 프로토콜은 AS 내부에서 수행하는지, 외부에서 수행하는지에 따라 종류를 나눌 수 있음
- **내부는 IGP(Interior Gateway Protocol), 외부는 EGP(Exterior Gateway Protocol)**

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/10.png)

### IGP : RIP와 OSPF

- **대표적으로 RIP(Routing Information Protocol), OSPF(Open Shortest Path First)**
- 최적의 경로를 선정하는 과정에서 **RIP는 거리 벡터**를, **OSPF는 링크 상태**를 사용하는 라우팅 프로토콜

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/11.png)

#### RIP

- **거리 벡터 기반 라우팅 프로토콜**로, 이름 그대로 **거리를 기반으로 최적의 경로를 찾는 라우팅 프로토콜**
- 거리는 패킷이 정유한 라우터의 수, 즉 **홉의 수 의미**
- 인접한 라우터끼리 경로 정보를 교환하며 라우팅 테이블을 갱신하는데, 이로 인해 특정 수신지까지 도달하는 홉 수를 알고. ‘홉 수가 가장 작은 경로’를 최적 경로

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/12.png)

#### OSPF

- **링크 상태 프로토콜**로, **링크 정보를 포함한 네트워크 상태를 그래프 형태로 링크 상태 데이터베이스에 저장**
- **라우터들의 연결 관계, 연결 비용 등 현재 네트워크 상태를 그래프로 표현하기 위한 데이터 저장**
- 라우터는 링크 상태 데이터베이스를 기반으로 현재 네트워크 구성을 마치 지도처럼 그린 뒤 최적 경로 선택

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/13.png)

- **대역폭 기반으로 메트릭 계산**
    - 대역폭이 높은 링크일수록 메트릭이 낮은 경로 인식
    - 라우터 간의 정보 주기적으로 교환하며, 라우팅 테이블을 갱신하는 RIP와 달리, **OSPF는 네트워크 구성이 변경이 있을 때만 갱신**
        - 변경될 때마다 갱신하면, 네트워크 규모가 클 때는 링크 상태 데이터베이스에 모든 정보 저장하기 어려워지는데
            
            → **에이리어(area) 단위로 나누고, 구분된 에이리어 내에서만 링크 상태 공유**
            
            에이리어 경계에 있는 ABR(Area Border Router)가 라우터가 에이리어간의 연결 담당
            

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/14.png)

### EGP : BGP

- **대표적으로 BGP(Border Gateway Protocol)로, AS간의 통신에서 사용되는 프로토콜**
    - AS내 라우터간 통신도 가능
- **AS  간의 통신을 위한 BGP는 eBGP(external BGP), AS 내의 통신을 위한 iBGP(internal BGP)**
- AS간 정보를 주고받기 위해 AS 내에서 eBGP를 사용하는 라우터 하나이상, 또 다른 AS의 BGP 라우터와 연결되어야함
- 이 연결은 BGP 라우터 간에 BGP 메세지를 주고받음으로써 이루어지는데, **BGP 메세지를 주고받을 수 있도록 연결된 BGP 라우터를 피어(peer)**라고 함
- AS와의 BGP 연결을 유지하기 위해 **BGP 라우터끼리 연결되어 피어 관계가 되도록 연결하는 과정을 피어링(peering)** 이라고 함

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/15.png)

- **BGP는 RIP와 OSPF에 비해 최적의 경로를 결정하는 과정 복잡, 일정하지 않음**
    - **경로를 결정하는 과정에서 주소와 더불어 ‘속성’, ‘정책’이 고려**되기 때문
    - BGP의 속성은 경로에 대한 부가 정보
    - 대표적 속성으로 AS-PATH, NEXT-HOP, LOCAL-PREF가 있음

#### 1. AS-PATH 속성

- **메세지가 수신지에 이르는 과정에서 통과하는 AS들의 목록**
- 메세지가 AS 거칠 때마다 AS-PATH에 거쳐 간 AS가 추가
    - **BGP(eBGP)의 특징**
    1. **BGP는 AS 간 라우팅을 할 때 거치게 될 ‘라우터’의 수가 아닌 ‘AS’의 수를 고려**
        - AS-PATH길이가 더 짧은 경로라 해도, 거치게 될 라우터의 홉 수가 더 많을 수 있음
    2. **BGP는 RIP처럼 단순히 수신지에 이르는 ‘거리’가 아닌, 메세지가 어디를 거쳐 어디로 이동하는지를 나타내는 ‘경로’를 고려**
        - BGP는 경로 벡터 라우팅 프로토콜이라고 부르기도 함

![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_03/03/16.png)

#### 2. NEXT-HOP 속성

- **이름 그대로 다음 홉, 다음으로 거칠 라우터의 IP주소 나타냄**

#### 3. LOCAL-PREF속성

- **지역 선호도, LOCAL PREFerence의 약자로, AS 외부 경로에 있어 AS 내부에서 어떤 경로를 선호할지에 대한 척도를 나타내는 속성**
- LOCAL-PREF 같은 AS 관리 주체가 설정하는 정책의 영향 받음
    - AS 내 라우터끼리 특정 경로에 대한 선호도를 합의한다는 것은 “정책적인 이유로 이 경로 우선시 하겠다”, “설령 이 경로가 다른 경로에 비해 비교적 비효율적일지라고 이 경로를 우선시하겠다”
