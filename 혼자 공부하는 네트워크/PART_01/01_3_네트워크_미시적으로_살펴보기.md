# 01-3 네트워크 미시적으로 살펴보기

네트워크에 연결된 두 컴퓨터가 메시지를 주고받으려면 정해진 규칙을 따라야 한다.  
데이터는 여러 계층을 지나며 전송에 필요한 정보를 얻고 수신지에서는 반대 순서로 처리된다.

## 프로토콜

- **프로토콜** : 통신 장치끼리 정보를 올바르게 주고받기 위해 합의한 규칙이나 방법
- 같은 프로토콜을 사용해야 서로의 메시지를 이해할 수 있다.
- 하나의 통신 과정에는 여러 프로토콜이 함께 사용된다.
- 프로토콜마다 목적이 달라서 패킷 헤더에 담기는 정보도 달라진다.

| 프로토콜 | 역할 |
| --- | --- |
| **IP** | 패킷을 수신지까지 전달 |
| **ARP** | IP 주소에 맞는 MAC 주소 찾기 |
| **HTTP** | 웹에서 정보를 주고받기 |
| **HTTPS** | HTTP + 보안 |
| **TCP** | 데이터를 신뢰성 있게 전달 |
| **UDP** | 신뢰성보다 빠른 전달에 집중 |

> 프로토콜은 하나만 사용하는 것 X
> 웹 통신을 할 때도 HTTP와 TCP와 IP 같은 여러 프로토콜이 함께 동작

## 네트워크 참조 모델

네트워크 통신 과정을 역할에 따라 여러 계층으로 나눈 구조

택배를 보낼 때 포장하고 송장을 붙인 뒤 배송하는 것처럼 네트워크도 정해진 단계를 거친다. 송신지에서는 위 계층에서 아래 계층으로 내려가고 수신지에서는 아래 계층에서 위 계층으로 올라간다.

### 계층으로 나누는 이유

1. **구성과 설계가 쉬워진다.**
   - 계층마다 담당 역할이 정해져 있다.
   - 필요한 프로토콜과 장비를 역할에 맞춰 구성할 수 있다.

2. **문제의 원인을 찾기 쉽다.**
   - 아래 계층부터 차례로 확인할 수 있다.
   - 케이블 문제인지 주소 문제인지 전송 과정의 문제인지 범위를 좁힐 수 있다.

## OSI 모델

통신 과정을 7개 계층으로 나눈 네트워크 참조 모델<br>
아래로 갈수록 통신 매체에 가깝고 위로 갈수록 사용자와 가깝다.

| 계층 | 이름 | 주요 역할 |
| :---: | --- | --- |
| 7 | **응용 계층** | 사용자에게 웹과 이메일 같은 네트워크 서비스를 제공 |
| 6 | **표현 계층** | 데이터를 변환하고 압축하거나 암호화 |
| 5 | **세션 계층** | 프로그램 사이의 연결을 만들고 유지하고 종료 |
| 4 | **전송 계층** | 신뢰성 있는 전송과 흐름 제어를 담당한다. 포트로 프로그램을 구분 |
| 3 | **네트워크 계층** | 다른 네트워크의 수신지까지 갈 경로를 정한다. IP 주소를 사용 |
| 2 | **데이터 링크 계층** | 같은 네트워크의 장치끼리 정보를 주고받는다. MAC 주소를 사용 |
| 1 | **물리 계층** | 비트를 전기와 빛 같은 신호로 바꾸어 통신 매체로 전달 |

### 계층별로 쉽게 보기

- **1계층**은 실제 신호가 이동하는 단계
- **2계층**은 주변 장치까지 전달하는 단계
- **3계층**은 여러 네트워크를 지나 목적지까지 길을 찾는 단계
- **4계층**은 데이터가 제대로 전달되도록 관리하는 단계
- **5계층**은 통신 연결 상태를 관리하는 단계
- **6계층**은 데이터의 표현 방식을 맞추는 단계
- **7계층**은 사용자가 이용하는 서비스와 가장 가까운 단계

## TCP/IP 모델

| TCP/IP 계층 | 역할 | 비슷한 OSI 계층 |
| --- | --- | --- |
| **응용 계층** | 사용자에게 네트워크 서비스를 제공 | 응용 · 표현 · 세션 |
| **전송 계층** | 신뢰성과 전송 흐름을 관리 | 전송 |
| **인터넷 계층** | 수신지까지 패킷을 전달 | 네트워크 |
| **네트워크 액세스 계층** | 네트워크 매체를 통해 데이터를 주고받음 | 데이터 링크 · 물리 |

- TCP/IP 모델은 **인터넷 프로토콜 스위트** 또는 **TCP/IP 프로토콜 스택**이라고도 부른다.
- 책이나 문서에 따라 네트워크 액세스 계층을 둘로 나눠 5계층으로 설명하기도 한다.
- OSI 모델과 TCP/IP 모델은 목적이 다르다. 계층을 억지로 일대일 대응할 필요는 없다.

## 캡슐화와 역캡슐화

### 캡슐화

송신 과정에서 상위 계층의 데이터에 현재 계층의 정보를 붙이는 과정이다.

- 원래 보내려는 내용은 **페이로드**가 된다.
- 각 계층은 페이로드 앞에 **헤더**를 붙인다.
- 데이터 링크 계층은 뒤에 **트레일러**를 붙이기도 한다.
- 완성된 데이터는 다음 하위 계층으로 전달된다.

```text
데이터
  ↓ 전송 계층 헤더 추가
세그먼트 또는 데이터그램
  ↓ 네트워크 계층 헤더 추가
IP 패킷
  ↓ 데이터 링크 계층 헤더와 트레일러 추가
프레임
  ↓ 신호로 변환
비트 전송
```

### 역캡슐화

수신 과정에서 각 계층이 헤더와 트레일러를 확인한 뒤 제거하는 과정

```text
비트 수신
  ↓
프레임
  ↓ 데이터 링크 정보 제거
IP 패킷
  ↓ 네트워크 계층 정보 제거
세그먼트 또는 데이터그램
  ↓ 전송 계층 정보 제거
원래 데이터
```

> **캡슐화는 포장하는 과정 & 역캡슐화는 포장을 푸는 과정이다.**

## PDU

**PDU**는 각 계층에서 주고받는 데이터의 단위다. 같은 데이터도 어느 계층에서 바라보는지에 따라 이름이 달라진다.

| OSI 계층 | PDU |
| --- | --- |
| 응용 · 표현 · 세션 계층 | 데이터 |
| 전송 계층 | TCP는 세그먼트<br>UDP는 데이터그램 |
| 네트워크 계층 | 패킷 또는 IP 패킷 |
| 데이터 링크 계층 | 프레임 |
| 물리 계층 | 비트 |

```text
데이터 → 세그먼트 또는 데이터그램 → 패킷 → 프레임 → 비트
```

## 트래픽과 네트워크 성능

- **트래픽** : 네트워크 안에서 주고받는 정보의 양
- **과부하** : 특정 장비가 처리해야 할 트래픽이 너무 많은 상태
- **처리율** : 단위 시간 동안 실제로 전송된 정보의 양
- **대역폭** : 단위 시간 동안 전송할 수 있는 최대 정보의 양
- **패킷 손실** : 전송 도중 일부 패킷이 목적지에 도착하지 못한 상태

처리율과 대역폭은 주로 `bps`와 `Mbps`와 `Gbps`로 나타낸다. 패킷 손실은 전체 패킷 중 사라진 패킷의 비율로 나타낸다.

`ping` 명령을 사용하면 수신지까지 패킷이 도달하는지 확인할 수 있다. 응답 시간과 패킷 손실 여부도 함께 볼 수 있다.

## 정리

- **프로토콜**은 장치끼리 정보를 주고받기 위한 규칙
- **네트워크 참조 모델**은 통신 과정을 계층으로 나눈 구조
- **OSI 모델**은 통신 과정을 7개 계층으로 표현
- **TCP/IP 모델**은 통신 과정을 4개 계층으로 표현
- **캡슐화**는 송신 과정에서 헤더와 트레일러를 붙이는 과정
- **역캡슐화**는 수신 과정에서 붙은 정보를 확인하고 제거하는 과정
- **PDU**는 각 계층에서 주고받는 데이터의 단위
