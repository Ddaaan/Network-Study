# 가용성

- 안정성 = 특정 기능을 언제든 균일한 성능으로 수행할 수 있는 특성

## 안정성을 나타내는 용어

### 가용성 Availability

- 컴퓨터 시스템이 특정 기능을 실제로 수행할 수 있는 시간의 비율
- 컴퓨터 시스템 = 서버, 네트웤, 프로그램 뭐든 될 수 있음
- 전체 사용 시간 중에 정상적인 사용 시간
    
    $\text{가용성}=\frac{\text{업타임}} {\text{업타임+다운타임}}$
    
    - 업타임 uptime = 정상적인 사용시간
    - 다운타임 downtime = 정상적인 사용이 불가능한 시간

### 고가용성 High Availability

- 가용성이 높은 성질
- 고가용성을 유지하는 것이 모든 웹 서비스 업체들의 목표
- 서비스가 다운되는 원인
    - 과도한 트래픽
    - 예기치 못한 SW상의 오류
    - HW 장애
    - 보안공격, 자연재해 등등
- 가용성을 높이려면 다운타임을 낮춰야한다
- 문제가 발생하더라고 기능할 수 있는 능력 = 결함 감내 fault tolerance
    - 결함을 감내할 수 있도록 서비스나 인프라 설계하는 것이 중요

# 이중화

- 무언가를 이중으로 두는 기술
- 결함을 감내하여 가용성을 높이기 위한 기본적이고 대표적인 방법
- 예비(백업)을 마련하는 방법
- 이중화할 수 있는 대상 = 문제가 발생할 경우 시스템 전체가 중단될 수 있는 대상
    - 서버 컴퓨터, 네트웤 인터페이스(NIC), 스위치 와 같은 물리적 장비
    - 데이터베이스, 웹 서버 프로그램 등
- 단일 장애점 SPoF; Single Point Of Failure
    
    문제가 발생할 경우 시스템 전체가 중단될 수 있는 대상
    

## 액티브/스탠바이 active-standby

- 액티브 = 가동상태
- 스탠바이 = 액티브의 백업으로 대기하는 상태
- 한 시스템은 가동하고, 다른 시스템은 백업 용도로 대기상태로 두는 이중화 구성 방식
- 액티브 상태인 시스템에 문제 발생 시, 스탠바이 시스템이 자동으로 대신하여 동작
- 성능상의 큰 변화는 기대하기 어려움

## 액티브/액티브 active-active

- 두 시스템 모두 가동 상태로 두는 구성 방식
- 부하를 분산할 수 있고 함께 가동되므로 성능상의 이점
- 한 시스템에 문제가 발생하면 다른 시스템에 부하 급증으로 문제

## 확장된 이중화 기술 = 다중화

- 무언가를 여러 개 두는 기술 (3개 이상)
- 이중화된 구성에 비해 더웅 안정적인 운영 가능

## 이중화/다중화 사례

- 이중화 = 티밍 teaming. 윈도우에서 사용되는 용오.
- 다중화 = 본딩 bonding. 리눅스에서 사용되는 용어
- 여러개의 네트워크 인터페이스(NIC)를 이중화/다중화하여 고성능의 하나의 인터페이스처럼 보이게 하는 기술

# 트래픽 traffic

- 주어진 시점에 네트워크를 경유한 데이터의 양
    
    ⇒ 주어진 시점에 특정 노드를 경유한 패킷의 양
    

## 과도한 트래픽의 문제

- 높은 부하로 인한 CPU 발화
- 수많은 트래픽 내용을 저장하는 메모리 공간의 부족함
- 제한된 대역폭과 병목 혀낭으로 응답 느려지거나 누락
- 프로그램 일관성이 손상

→ 가용성을 떨어트림

## 로드 밸런싱 load balancing

- 트래픽의 고른 분배를 위해 사용되는 기술
- 부하를 의미하는 로드 load와 유지를 나타내는 밸런싱 balancing이 합쳐진 단어
- 로드 밸런서 load balancer에 의해 수행
    
    ![image.png](../../IMG/혼자%20공부하는%20네트워크/PART_07/01/image(1).png)
    
    - 이중화나 다중화된 서버와 클라이언트 사이에 위치
    - 클라이언트 : 로드 밸런서에 요청 보냄
    - 로드 밸런서 : 해당 요청을 서버에 균등하게 분배

## 로드 밸런싱 알고리즘

- 로드 밸런서가 요청을 전달할 수 있는 서버가 여러개 있을 경우
    
    부하가 균등하게 분산되지 않도록 부하 대상을 선택하는 방법
    

### 라운드로빈 알고리즘 round robin algorithm

- 단순히 서버를 돌아가며 부하를 전달하는 알고리즘
- 서버마다 가중치 부여 = 가중치가 높은 서버가 더 많이 선택되어 더 많은 부하를 받도록
- 가중치 라운드 로빈 알고리즘 weighted round robin algorithm

### 최소 연결 알고리즘 least connection algorithm

- 연결이 적은 서버부터 우선적으로 부하를 전달하는 알고리즘
- 가중치 최소 연결 알고리즘 weighted least connection algorithm
    - 서버간 성인이 다른 경우에는 가중치가 적용된 알고리즘이 사용
